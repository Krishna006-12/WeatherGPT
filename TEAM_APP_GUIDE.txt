3. HOW TO RUN (local + deploy)
================================================================================
  Prerequisites: Node.js 18+ , npm, Git Bash / terminal

  --- Local frontend ---
  cd weathergpt
  rm -f postcss.config.js          # Tailwind v4 break karta hai yeh file
  npm i
  npm run dev                      # http://localhost:5173
  npm run build
  npm run preview

  --- Full serverless APIs locally ---
  npx vercel dev                   # /api/* real functions (climate, models, alerts…)
  Note: plain `npm run dev` only proxies weather/geocode/aqi to Open-Meteo.
        alerts/climate/models/public need Vercel functions OR client fallbacks.

  --- Production deploy ---
  npm i && npm run build
  npx vercel login                 # pehli baar
  npx vercel --prod
  Phir HARD REFRESH (Ctrl+Shift+R). Purana Service Worker ho to:
    DevTools → Application → Service Workers → Unregister → refresh

  --- Important deploy gotchas ---
  * Agar /api/* HTML return kare = SPA rewrite ne API kha liya, ya api/ missing
  * vercel.json rewrites: /api/ ko index.html pe mat bhejo
  * postcss.config.js extract ke baad DELETE
  * Zip se deploy: weathergpt-deploy.zip extract → upar wale steps

5. ARCHITECTURE (simple)
================================================================================

     [ User Phone / Laptop browser or PWA ]
                    |
                    v
            React SPA (Vite)
            - Dashboard, Chat, Alerts, Modes, Climate…
            - localStorage prefs / chat history
                    |
         fetch JSON (same origin /api/*)
                    |
                    v
         Vercel Serverless (api/*.js)
                    |
        +-----------+-----------+--------------+
        |           |           |              |
        v           v           v              v
   Open-Meteo   Open-Meteo   GDACS        Open-Meteo
   forecast     archive      events       Flood API
   + multi-model

  NO database yet (planned next). Identity = browser localStorage only.
  Weather numbers always from live upstream (or short offline pack fallback).

6. FRONTEND — TABS & SCREENS
================================================================================
  Bottom nav (mobile) / Sidebar (desktop ≥1024px):

  HOME (DashboardTab)
    - Soft blue weather hero (temp, condition, metrics)
    - Dark sheet: Today hourly / 5-day
    - AI Brief: What's happening → Expect → Do (+ confidence)
    - Alert strip, Today's decisions (Travel/School/Farm) + Why?

    - LIVE / OFFLINE truth from weather.live

  CHAT (ChatTab)
    - NL questions Hindi/English
    - Mic = speech-to-text (hi-IN / en-IN)
    - Listen button = text-to-speech on assistant answers
    - Intent routing in services/ai.js (rain, alert, farm, travel, school,
      forecast, predict, climate, models, aviation-lite, …)
    - Answers grounded on current weather pack + optional other city fetch
    - Source line + confidence on each reply

  ALERTS (AlertsTab)
    - Here = current city weather.alerts

    - Severity chips SEVERE/HIGH/MODERATE/LOW

  MODES
    - FarmTab   : soil, irrigation, spray window (from weather.agri)
    - TravelTab : road risk, visibility, safer windows (insights)
    - SchoolTab : heat / outdoor PE (insights)

    - ForecastTab : hourly/daily charts + plain language + sources
    - ClimateTab  : 12-month climate charts + NWP model comparison  [SIH]
    - CitiesTab   : search + recent + curated India cities
    - SettingsTab : lang, °C/°F, home city, notify prefs, permission, onboarding

  OTHER UI
    - Onboarding first visit
    - About modal (product + external AI test links)
    - ErrorBoundary (blank page se bachav)
    - Device lab ONLY at ?preview=1  (M/T/D/F frames) — normal open pe NAHI

7. BACKEND APIs (team + external AI)
================================================================================
  Base: https://YOUR-DEPLOY-URL

  GET /api/weather?lat=&lon=&tz=&name=
      Live Open-Meteo forecast + live_alerts[] (GDACS, flood, model)

  GET /api/alerts?lat=&lon=&name=
  GET /api/alerts?points=lat,lon,Name|lat2,lon2,Name2&radiusKm=600
      Multi-source alerts near one or many places

  GET /api/climate?lat=&lon=&name=
      Historical monthly temp/rain + 12m vs prior window deltas (archive)

  GET /api/models?lat=&lon=&name=
      GFS / ECMWF / ICON / best_match snapshot + ensemble spread

  GET /api/aqi?lat=&lon=
  GET /api/geocode?q=&count=&language=

  GET /api/public
      Discovery JSON for bots/judges (no auth, CORS *)

  GET /api/public?action=chat&q=...&lat=&lon=&name=&lang=en
      Stateless NL answer — other AIs call THIS if they cannot open SPA

  GET /api/public?action=bundle&lat=&lon=&name=
      Compact weather JSON

  Static (no JS needed for humans/bots):
      /llms.txt       /sih.html       /openapi.json       /robots.txt

  CORS: Access-Control-Allow-Origin: * on APIs
  Auth: none (demo). Rate limits = upstream free tiers — don't hammer.

8. CLIENT SERVICES (src/services/) — kya karta hai
================================================================================
  weather.js
    - fetchWeather(city): proxy /api/weather → else direct Open-Meteo → offline pack
    - parse pack: current, hourly, daily, agri, alerts merge, sources[], live flag
    - injectSimulatedAlert() for judge demo RED
    - clearCache()

  ai.js
    - chat(message, { weather, lang, fetchWeatherFor })
    - Intent detect + rich markdown answers (HI/EN)
    - welcomeMessage()
    - Does NOT invent temperatures; uses wx pack

  insights.js
    - buildPrediction, buildTravelInsight, buildSchoolInsight, estimateVisibility

  briefing.js
    - buildStructuredBrief (What/Expect/Do)
    - buildDailyBriefing + shareBriefing (Web Share / clipboard)

  aqi.js          - Open-Meteo Air Quality (+ /api/aqi fallback)
  geocode.js      - place resolve + aliases (Noida etc.)
  climate.js      - client fetchClimate + fetchModels
  notifications.js
    - permission, show notification, multi-city watch list, fetchLiveAlertsFeed
    - dedupe keys in localStorage (no spam)
  voice.js        - TTS speak/stop + plain text strip
  storage.js      - prefs, onboarding, chat history keys

  hooks/useAlertMonitor.js
    - Poll ~every 3 min when notifyAlerts on
    - Seed seen on first fetch; later only NEW alerts notify

10. NOTIFICATIONS — kaise kaam karti hain
================================================================================
  1) User Alerts tab → Enable notifications → browser Allow
  2) Monitor on (prefs.notifyAlerts)
  3) useAlertMonitor polls /api/alerts for home + metros (Kanpur, Delhi, …)
  4) New alert notifyKey not in seen set → Notification API / SW showNotification
  5) Click notification → /?tab=alerts (sw-push-click.js)

  Limits:
    - Needs HTTPS + permission
    - Works best when tab/PWA available; full FCM when app killed = future
    - First poll seeds seen (no backlog spam)
