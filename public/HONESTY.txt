3) DATABASE / SUPABASE
----------------------
No cloud DB / no Supabase in the shipped app.
On-device only:
  - localStorage: prefs, chat history, recent cities, notification dedupe, onboarding
  - IndexedDB (weathergpt_db): slim weather_cache packs + alert_events audit + kv mirror
    for offline / low-bandwidth (last-good pack labelled — never fake LIVE)
Postgres/Supabase may appear in docs as PLAN, not as live product.
Do not tell judges "we use Supabase" unless the env + client are connected.

4) ALERTS — WHAT IS LIVE
------------------------
LIVE sources used:
  - GDACS multi-hazard (distance-filtered)
  - Open-Meteo Flood (river discharge signal)
  - Open-Meteo meteo thresholds (colour philosophy similar to IMD UX)
NOT live:
  - Official IMD district warning polygons (need IMD API key / terms)
  - Guaranteed SMS to every feature phone in a district

Browser/PWA notifications: implemented (permission + poll + dedupe).
True push when phone is fully off: needs FCM/APNs + backend (planned).
